## KiraAI Reminder Plugin v2.3.0

本版本集中改进提醒的投递状态、群聊来源识别、多适配器权限、数据与调度可靠性，以及 WebUI 使用体验。内部代码按职责拆分，便于后续维护；不需要修改 KiraAI 主项目代码。

### 新增与改进

- **提醒投递回执与补救**：包含提醒的模型调用正常返回后，才清理一次性提醒。失败、超时或结果不明时保留记录，可通过 WebUI 或具有权限的 LLM 工具检查和处理。
- **按需识别群聊请求来源**：多人消息合批时，LLM 可通过 `list_message_sources` 获取当前批次的来源标记，为对应用户设置普通个人提醒；其他相关管理操作采用轻量确认，不默认归给最后一位发言人。
- **适配器级身份与权限隔离**：用户和聊天管理员按“适配器名称＋用户 ID”识别，同号不跨适配器合并。旧提醒及投递快照支持带备份的身份迁移，旧裸 ID 权限需要明确归属适配器。
- **重复提醒日期更清晰**：每日／每周／每月／每年的日期作为开始约束与周期锚点，不在每次执行后改写。查询与看板分别展示“开始”和实际登记的“下次”；暂停或调度不可用时显示状态。
- **随机提醒批量保护**：单次新建最多 100 条，同一新建批次不重复占用同一分钟；参数无效或超限时整批拒绝，旧任务不受新建数量限制影响。

### 可靠性修复

- 调度注册失败不再返回创建成功；文件保存失败保留原运行任务，调度变更失败尝试补偿，补偿不完整时明确反馈。
- 自主规划后台任务合并最新状态，避免旧快照覆盖并发创建或更新的意图。
- 自主意图更新先校验全部参数，无效请求不再保存部分修改。
- 已存在但无法读取、JSON 损坏或自主状态结构不合法的数据会保留并报错，不作为空数据覆盖。
- 插件自身的旧高级配置迁移增加原配置校验、首次备份和原子替换保护，保留自定义提示词及已有字段优先级。

### WebUI 改善

- 修复待处理投递的重试／忽略交互，保留必要确认及重要提醒删除保护。
- 请求期间防止重复提交；超时、失败、结果不明和旧请求晚到均有对应状态处理。
- 操作后的刷新保持列表和焦点，减少页面跳回顶部；手动扫描同步更新会话与用户筛选名单。
- 通知数量有上限，相同通知合并，支持关闭，并优先保留错误信息。
- 修复通知悬停背景、状态边框、窄屏布局和长内容溢出。
- 前端 JS、CSS、字体与许可证随插件本地分发，不再依赖外部 CDN；普通安装与运行不需要 npm 或前端构建。

### 升级注意事项

1. **升级前备份**插件数据目录 `data/plugin_data/reminder_plugin/` 和插件配置 `data/config/plugins/reminder_plugin.json`。保留已有备份，不需要卸载插件或删除数据。
2. 管理员／授权用户配置采用 `适配器名称:用户ID`，例如 `QQ:123456`。适配器名称区分大小写，必须与会话 ID 前缀一致；`QQ` 与 `qq` 不自动视为同一个适配器。
3. 单一适配器配置可自动固定旧裸 ID 的归属；多个已配置适配器时，应指定 `legacy_acl_adapter` 或将旧权限改为带适配器名称的格式，避免失去预期授权。
4. 已保存的自定义 `usage_prompt` 不会被新版默认值覆盖。如需采用新版使用说明，可参考[已确认的提示词方案第 2.4 节](https://github.com/xgrbhc/KiraAI-Reminder-Plugin/blob/main/docs/PROMPT_CHANGE_PROPOSAL.md)，在高级配置中手动更新。
5. 升级后按原部署方式重载／重启，再强制刷新浏览器。发现数据读取错误时，先备份并修复文件或权限，不要直接清空原文件。

### 兼容性与边界

- 插件声明的最低 KiraAI 版本为 `>=2.24.2`；本轮在 KiraAI `v2.34.8` 环境验证，不代表逐一验证了所有核心版本及真实适配器组合。
- “LLM 已收到／处理”不等于平台发送成功、用户已阅读或任务已完成。
- 结果不明或包含 `action` 的投递不会被盲目自动重试。LLM 仅可对明确失败且无动作的记录按权限重试／忽略；其他情形需 WebUI 确认或延后检查。
- `defer` 只是延后 24 小时提供自动问题摘要，不会创建自动唤醒或自动重试任务。
- 群聊中的普通提醒仍归属于具体用户，不是全群共有任务；群聊查询结果可能展示给群成员，私密管理请使用已认证的 WebUI。
- 高级配置迁移保护只覆盖插件自身路径，不覆盖主项目默认配置填充或 WebUI 配置保存，不承诺跨进程事务或整条配置链路断电安全。
- 前端不新增自动轮询，实际下次计划和任务状态在查询／扫描等已有刷新时更新。
