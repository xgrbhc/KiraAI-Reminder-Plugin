## 下一版优先项：随机批次重新排程

当前随机批次是多条独立的一次性任务，通过 `random_batch_id` 关联，并非一条可直接修改的随机规则。困难主要在范围、历史和并发一致性，不在生成随机数。

1. 提供独立的“重新排程”入口。输入新时间范围与未来次数，明确次数指剩余待执行项，不能把历史完成数算回去。
2. 先生成预览，展示实际抽取时间、保留历史数与将替换的未来任务数。预览后保存使用同一组时间，不能二次随机。
3. 只替换未触发项；已触发、处理结果不明的投递与历史记录原样保留。提交前重新检查批次快照和预览有效期，期间到期则要求重新预览。
4. 在一个存储事务中替换，沿用调度补偿；为新任务使用新 ID，保留来源、归属与批次关联，避免旧回执清理新任务。
5. 明确暂停与重要标记的继承规则；已有混合状态时展示分歧，不能静默统一。时间容量不足时明确拒绝或让用户调整，不静默减少次数。
6. 同步提供 LLM 原生预览／提交能力，工具和 WebUI 使用同一服务，权限在提交时再次校验。

验收至少包含：部分任务已完成、保存期间触发、重复提交、旧回执晚到、调度部分失败、预览过期、极短窗口与最大批次数量。通过后再决定发布，不与 v2.5.0 基础编辑混合上线。

## 再后续考虑

自主跟进编辑应落在意图管理界面，并同步意图状态与跟进任务，不能直接改底层提醒使两边脱节。随机批次聚合显示和批次星标可在重新排程的数据语义明确后推进。已有浏览器／代理缓存场景继续收集部署证据，不扩大为主项目修改。
