# v2.3.1｜投递记录简化与待办查询修复

本版本让投递时间更准确，并将待处理投递简化为可查询、可忽略的信息记录；原待办与投递问题分开管理，历史异常不再阻塞后续周期提醒。

> **升级前请留意：本版包含投递管理行为调整，不是完全兼容的补丁升级。** 投递记录不再提供重试／延后；忽略记录不再删除原单次待办。旧工具或 API 调用中的 `retry`／`defer` 会被拒绝，不会重新执行动作。

## 修复与改进

- **触发时间显示准确**：待处理投递显示本条实际尝试的触发时间，不再误用周期提醒的开始日期。旧补建或缺少可靠时间的记录明确显示未知，合并记录另列最近周期触发时间。
- **完整待办列表查询恢复正常**：修复保留过期单次待办时，列表误读 `next_run_time` 导致整个查询失败的问题。单次提醒沿用原定时间，周期提醒仍显示开始与下次执行时间。
- **周期计划继续运行**：历史失败／未确认不再阻止下一次真实周期投递；连续异常合并展示，各次新尝试仍有独立回执。同次防重复与等待超时保护继续保留。
- **投递处理更简洁**：WebUI 与 `review_delivery_issue` 仅支持忽略；工具的 `decision` 可省略，默认 `dismiss`。失败、未确认及旧补建记录，包括含动作记录，均可在现有身份、来源和权限检查通过后忽略。
- **原待办不受忽略影响**：忽略仅标记投递问题，不删除或修改原待办，不改变重要标记、暂停状态或未来周期计划。保留的过期单次待办在 WebUI 标记为“已过期（保留）”，不计入活动数量；重启后不会重新补建同一条已忽略异常。

## 升级注意事项

1. 升级前备份 `data/plugin_data/reminder_plugin/` 与 `data/config/plugins/reminder_plugin.json`；不要卸载插件或清空原数据。
2. 更新插件后，按原部署方式重载／重启 Kira，再强制刷新 WebUI。普通安装与使用无需 npm 或重新构建前端。
3. **未确认不等于未执行。** 如需补做，由用户或 LLM 结合上下文另设单次任务，避免重复执行动作或复制周期计划。本版不会自动补发历史周期。
4. 若要移除保留的过期单次待办，请使用原待办删除功能；忽略投递不是删除待办。正常模型接收成功后的单次清理流程保持不变，旧版已经删除的待办不会自动恢复。
5. 使用旧 `retry`／`defer` 参数的脚本、集成或保存的自定义提示词，需要按新行为自行调整。默认／保存的 `usage_prompt` 不会因此被自动改写；普通 `list_reminders` 查询参数不变。

## 兼容性与验证

- 不修改 KiraAI 主项目代码；最低声明版本仍为 `>=2.24.2`。身份、适配器大小写隔离、群聊来源确认、重要待办删除保护及自主模式限制保持不变。
- 模型可见的投递工具说明、查询时间与本轮临时摘要已同步；摘要仍有界、仅本轮使用，不改写主项目历史或缓存。
- 发布准备阶段验证：插件 Python 回归及显式审计探针共 **715 项通过**，前端 Node 回归 **66 项通过**；主项目关联回归此前 **37 项通过**。新增完整列表组合回归 21 项，覆盖过期单次、随机／自主单次、周期混合、忽略、启动恢复及权限筛选。
- 测试使用临时文件和模拟事件，另有隔离浏览器点击检查；不等于逐一验证所有真实平台或模型，也不保证平台发送、用户阅读或动作完成。
