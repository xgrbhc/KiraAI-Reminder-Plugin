# 旧高级配置迁移写入保护

## 1. 问题与范围

插件构造时的 `_migrate_advanced_config()` 把旧顶层高级字段移到 `advanced_config`。当前直接 `Path.write_text()` 覆盖文件；写入中断可能只留下部分 JSON，且没有该迁移专用的原始备份。

现有权限配置绑定已使用 `ReminderStorage` 原子替换，本轮不重写该流程或身份迁移。`core/utils/` 中未发现适合插件配置的公开通用原子 JSON 保存接口；核心更新事务是专用接口，不引入新的核心内部依赖。复用插件自身已采用的同目录临时文件、flush/fsync、os.replace 写法。

重要边界：主项目 PluginRegistry 在插件构造之前填充并直接保存 schema 默认配置，WebUI 配置保存也属于核心。插件不能保护此前／后续核心写入；本轮不改核心、不猴子补丁，不承诺端到端断电恢复或跨进程事务。

## 2. 保持不变

- 仅旧字段实际需要迁移时触发落盘；无迁移时不读写配置或生成备份。
- 既有优先级不变：高级字段等于默认值时采用旧顶层值；已有高级自定义值优先；删除已迁移的顶层旧字段。缺失高级分组仍不在此处自动创建。
- 保留配置中的未知字段、其他分组以及用户自定义提示词的原字符串；不修改 schema、默认提示词、LLM 工具说明、权限或适配器格式。
- 不修改传入配置字典；迁移保存失败仍按既有行为返回内存中的转换结果并警告，不新增整个插件停用或用户确认流程。
- 配置路径和 JSON 四空格格式不变；无旧文件时允许创建，不生成虚假“旧文件备份”。

## 3. 写入保护

- 已存在配置先按 UTF-8 读取并确认是 JSON 对象；不可读、损坏或非对象时不覆盖。区分“文件不存在”和“已存在但读不到”。
- 首次备份为配置目录下 `reminder_plugin.pre-advanced-config.backup.json`，保存迁移前文件的精确字节。不覆盖已有备份；已有备份不可读或不是有效 JSON 对象时拒绝本次落盘，留给人工检查。
- 新备份以独占方式创建并 flush/fsync；正常异常中若只写入部分内容，清理本次自己创建的残留备份。进程强杀可能留下不完整备份；再次迁移会验证并拒绝使用它，不会自动覆盖。
- 完整迁移内容先序列化，再写入同目录唯一临时文件，flush/fsync 后原子替换目标。序列化、备份或替换失败不截断原配置；正常异常清理本次临时文件，成功备份继续保留。
- 将原子 JSON 写法提取为存储模块内的小函数，提醒／投递／自主数据沿用原校验和锁；配置保存为构造阶段同步调用，不在运行中的事件循环内嵌套 `asyncio.run()`。
- 不新增跨进程锁、后台迁移、数据库或并发修改检测；默认单实例启动迁移，不把读取与替换之间的窗口宣称为跨进程事务。若配置在别处保存，应按既有方式重载。
