# 自主意图更新参数校验修复（R4）

状态：代码修复、隔离回归及用户重启后的简单正常使用验收已完成（2026-10-04），用户已授权单独提交 R4。基线提交 `aee8f75`；修复提交标识以 Git 历史为准。

## 问题与改法

原 `update_intent()` 在存储事务内先修改标题、备注，再验证 status、priority。参数无效时返回错误，但正常退出 `modify()` 仍会保存之前的修改。错误返回与实际结果不一致。

改为先准备候选字段并验证全部参数，通过后才进入存储事务，读取最新目标，一次性更新字段与 `updated_at`。参数错误不进入读写事务，不改变原意图或触发保存。

参数校验提前后，无效参数优先返回原参数错误；参数有效但目标不存在时仍返回原“找不到自主意图”提示。错误文案不改，不新增确认步骤。

## 保持的行为与边界

- title 为 None 或空白时仍不修改标题；notes 保持现有空值、去空白处理。
- status 仍支持 active、paused、waiting_confirmation、closed；None 表示不修改。
- priority 仍转换为数字并按原逻辑限制到 0~1；不在本轮改变范围处理或引入更严格规则。
- 未提供字段时仍允许只刷新 `updated_at`；不重写未知字段，不改变目标 ID 或下一次跟进安排。
- 只改插件 `autonomy.py`、相关测试和文档；不改主项目、提示词、工具描述、权限、前端或配置说明。
- 参数有效但目标不存在的既有会话默认字段处理不在本轮重构；嵌套损坏保护、跨文件事务和其他接口的业务规则留在独立问题中。
- 不重启、修改真实意图或调用真实 LLM；用户验收并授权后单独提交 R4，不推送，也不混入 R5/R6。
